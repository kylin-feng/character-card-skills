## 三、参考图路线（用户已确认）

最稳的做法**不是文生图**，而是：

1. 用户把 `assets/refs/` 三张图传进豆包
2. 用「以我上传的图为参考，保持外貌完全一致」生 **基准图**（半身正面、纯白背景）
3. 确认满意后，**之后所有图都以基准图为参考**，不要回头用原始三张
4. 再依次做三视图 → 表情差分 → 场景图
5. **一次只改一个变量**（换场景就别同时换表情，崩了不知道哪出问题）

完整指令模板见 `references/comic-prompts.md`。

## 四、踩坑清单（写给下一个接手的人）

这个项目犯过两次错，都已修正，别重复：

1. **没读图就写视觉细节**。用户传了图，起初没读（图只在聊天里、无本地路径），
   却编出了配色表和材质细节，还写得像测量过的。
   后来用户把图存到本地，实读后发现 **5 处描述是错的**（尤其漏了蓝灰色肩带）。
   → **没有本地路径就是看不见，要说出来；有路径就一定要真读。**

2. **能力声明说早了**。一度说「我生不了图」，后来生图技能出现，说法失效；
   但那个 MCP 工具其实仍未接入。
   → **动手前先查工具在不在可用列表里，别凭技能文档存在就假定能用。**
