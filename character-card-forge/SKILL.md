# 角色卡锻造 · Character Card Forge

> 「先定形象，再定灵魂，最后才谈格式。」

## Overview

把一段描述、几张参考图或一个名字，锻造成**可直接使用**的角色卡三件套：

| 产物 | 用途 |
|---|---|
| 人设设定集 Markdown | 给人看的完整设定 |
| `chara_card_v2` JSON | 直接导入 SillyTavern / 酒馆 |
| AI 漫剧形象卡 | 生图指令、分镜、表情差分、TTS 参数 |

**本技能只管「建卡」这件事本身，不管单纯的出图或扮演。**

## When to Use

**明确触发**：「做个角色卡」「人设卡」「character card」「酒馆卡」「SillyTavern 卡」
「chara card」「做个人设」「锻造角色卡」

**模糊触发**：「帮我设计一个角色」「根据这张图做个人设」「我想要个 AI 女友/男友设定」
「给这个角色写背景故事」「做个 AI 漫剧的主角」「这个角色的世界书怎么写」

**不触发**：

- **单纯生成一张图**（单张头像/插画/海报，没要角色卡结构）→ 走 `media-generation`，
  那条路不通则走 `minimax-media`。
  用户只说「画一张/生一张」而没说「卡/设定/分镜/世界书」，就不是本技能
- **单纯聊天扮演** → 直接对话。「扮演一个傲娇猫娘跟我聊」只要动词是「扮演/聊天/对话」
  且没出现「卡/设定/世界书/分镜/酒馆导入」，就不要触发本技能
- 写小说正文或剧本对白
- 给真实存在的人物做视角分析（那是 `*-perspective` 类技能）

## 推荐模型

| 环节 | 推荐 | 理由 |
|---|---|---|
| **生图** | **豆包 Seedream 4.0**（`doubao-seedream-4-0`） | 支持多图输入做角色一致性，中文提示词理解好，支持 4K |
| 生图·可直连 | **MiniMax `image-01`**（走 `minimax-media` 技能） | **已实测可用**；`subject_reference` 支持单图人物主体参考 |
| 生图·备选 | Midjourney `--cref` / NanoBanana | 角色引用成熟；无豆包时用 |
| **写卡文本** | 当前对话模型即可 | 纯文本创作，无特殊要求 |
| **视频化** | MiniMax H3 | 漫剧分镜转动态时用，768P/5s 起步 |

### 生图工具：先查，再决定路线 ⚠️

动手前**先确认可用工具**，按优先级降级：

1. `mcp__media__generate_image`（media MCP，走公司 API）—— 需连接器已接入；**先看连接器列表**
2. 内置 `ImageGen` —— **必须先 `ToolSearch` 确认存在，不是每个会话都有**
3. **`minimax-media` 技能** —— 走 MiniMax 官方 API，**已实测可用**（文生图 + `--ref` 人物主体参考）
4. 都没有 → **不要假装能生图**，改为输出「可直接粘贴进豆包的指令文本」，
   并明确告诉用户图要他自己生

> 📌 已实测存在「前两档都没有」的环境（连接器只有 Agent Mail，`ImageGen` 搜不到），
> 这正是补上第 3 档 `minimax-media` 的原因。此时**不许假装能生图**。
> `VideoGen`（视频）有时反而可用，但按秒计费，**用前必须先告知费用并取得同意**。

**要走 API 就走 `minimax-media` 技能里封装好的脚本**，不要手写 curl 或临时拼请求字符串——
凭据读取、参考图 base64 编码、错误码翻译、结果落盘它都已经处理好了。

## 执行流程

### Phase 0 · 澄清（最多问 3 个，信息够就跳过）

1. **格式**：Markdown 设定集 / 酒馆 JSON / 漫剧卡 —— 要哪些？（可多选）
2. **基调**：由我按素材发挥，还是你已有设定要我成卡？
3. **尺度**：全年龄向 / 成人向？（默认全年龄向）

名字、性别、世界观等缺失项，**先按素材合理发挥并标注「待确认」**，不要逐条盘问。

### Phase 1 · 形象锚定（有图必做，这步决定一切）

#### 1.1 读图 —— 强制检查点 ⚠️

用户给了参考图时：

- 图**在本地磁盘** → **必须用 `Read` 工具真实读取**，再写外貌描述
- ⚠️ 若 `Read` 报 `does not support reading images`（当前模型不支持视觉）→
  **本轮就是看不到像素**，按下面「只在聊天里」的同一条规则处理。
  **别因为路径有效就以为读到了** —— 文件存在 ≠ 你看见了内容
- 图**只在聊天里**（附件/粘贴，无本地路径） → 你**看不到像素**。此时：
  - ❌ 不许编造十六进制色值、材质、光影细节
  - ✅ 外貌描述只写**结构性特征**（发型长度、有无兽耳、服装类型、配饰位置）
  - ✅ 生图指令改为**参考图路线**：让用户自己把图传进豆包，指令里写
    「以我上传的图为参考，保持外貌完全一致」，颜色交给参考图自己说话
  - ✅ 主动告诉用户：「配色表我没法给准确值，等你出图后我再补」

> **这是本技能最容易翻车的地方。** 凭想象写出的 `#DDE1E8` 看起来专业，实则是编的。
> 宁可留空，不可假装。

#### 1.2 提炼「外貌锚点」

列出**不可更改的识别特征**（发色发型 / 兽耳 / 瞳色 / 标志性配饰 / 服装款式 /
特殊符号如光环刺青）。每条都要能被生图模型理解，**不要写「气质优雅」这种废话**。

#### 1.3 设计「情绪外显道具」（强烈建议）

给角色一个**随情绪变化的可视元素**——光环明暗、耳朵动作、尾巴摆动、
瞳孔纹样、发梢颜色。一石三鸟：

- **性格约束**（如「光环会闪 → 她说不了谎」）
- **画面素材**：每句台词都有可写的画面细节（漫剧分镜素材）
- **防 OOC 锚点**：模型有稳定的行为锚点

### Phase 2 · 灵魂构建

**性格三层**（避免扁平人设）：

| 层 | 内容 |
|---|---|
| 表层 | 别人第一眼看到的（温柔 / 毒舌 / 高冷） |
| 中层 | 相处后才发现的（其实固执 / 其实心软） |
| 里层 | 他自己都不愿承认的（恐惧、缺失、执念） |

**再加三样**：

- **一句话核心**：用一句话概括这个角色的内在矛盾
- **反差萌点** 3 条：具体、可互动（怕辣、唱歌跑调、被摸耳朵会宕机）
- **OOC 红线**：明确列出「这个角色绝不会做的事」

**背景故事**：控制在 200–400 字，要有一个**转折点**（他为什么变成现在这样）。
不要写编年史。

### Phase 3 · 出卡（按 Phase 0 选择）

#### A. Markdown 设定集

基础档案表 → 外貌锚点 → 配色表（无图则留空标注）→ 性格三层 → 背景 →
能力（含**限制**，无限制的能力是废设定）→ 喜好习惯口癖 → 关系称呼 →
语气示例 5 条 → OOC 红线 → 名字含义

#### B. 酒馆 JSON（`chara_card_v2`）

骨架见 `references/chara-card-v2.json`。要点：

- `description`：外貌 + 情绪道具 + 性格 + 背景 + 能力，**用方括号分段**（`[外貌]`）
- `first_mes`：**必须有场景、动作、对话三要素**，200–400 字，`*斜体*` 写动作
- `mes_example`：**至少 4 组**，每组 `<START>` 开头，要覆盖不同情绪面
- `alternate_greetings`：3 条，分别对应不同场景/情绪
- `character_book`：**5–8 条**，keys 用用户真会打出的词
- `post_history_instructions`：写行为约束（如「每次回复须体现光环状态」）
- ⚠️ 用 `{{user}}` 和 `{{char}}` 占位，不要写死名字
- ⚠️ 不替 `{{user}}` 决定行动或代写台词——写进约束里
- ⚠️ 写完后**重新解析验证** JSON 是否合法

#### C. 漫剧形象卡

核心锚定指令（中文自然语言）→ 负面词 → 三视图指令 → 表情差分 →
场景库 → 镜头语言 → 示例分镜 → TTS 参数 → **一致性避坑清单**

> ⚠️ **提示词方言别搞混**：豆包 Seedream 吃**自然语言长句**，
> **不要用 `(keyword:1.3)` 权重语法**——那是 Stable Diffusion 的写法，
> 在豆包里无效甚至帮倒忙。给 SD/ComfyUI 用才写权重版。

### Phase 4 · 生图（可选，且需前置检查）

确认生图工具可用时，推荐顺序：

1. **基准图**：半身正面、纯白背景 → 用户确认满意
2. **之后所有图都以基准图为参考**，不要回头用原始素材
3. 三视图 → 表情差分 → 场景图

> 走 `minimax-media` 时，第 2 步就是把基准图传给 `--ref`（人物主体参考）。
> 它**一次只接受 1 张参考图**，所以基准图必须出得干净、脸要正、五官无遮挡。
4. **一次只改一个变量**（换场景就别同时换表情，崩了不知道哪出问题）
5. 交付**本地文件路径**给用户，不是 URL

工具不可用时：输出可粘贴的指令文本，说清楚要用户自己去豆包生成。

## 交付

默认写到 `<用户桌面>/<角色名>角色卡/`：

```
<角色名>角色卡/
├── 1-<角色名>-人设设定集.md
├── 2-<角色名>-SillyTavern角色卡.json
├── 3-<角色名>-AI漫剧角色卡.md
└── refs/                    ← 参考图归档（若用户提供了图）
```

交付时说明：文件路径、酒馆导入方式（JSON 可直接导入；要 PNG 卡需用在线工具
把 JSON 写入图片元数据）、以及**哪些内容是推断的、需要用户确认**。

## 诚实边界

**做不到的**：

- ❌ **看不见只存在于聊天里的图片**——没有本地路径就读不了像素
- ❌ 不能凭空给出准确配色值，除非真读了图或用户告知
- ❌ 生图通道（media MCP / `ImageGen` / `minimax-media`）全都不可用时不能生图，也不会假装生成了
- ❌ 不做真人角色卡（真实人物请用 `*-perspective` 类技能）
- ❌ 不保证生成图跨镜 100% 一致——文生图有随机性，参考图路线只是显著改善

**会主动说的**：

- 哪些设定是我发挥的，哪些是用户给的
- 配色/材质等视觉细节的来源（读图 vs 推断）
- 成人向内容需用户明确要求，默认全年龄向

## 验证清单（交付前自查）

- [ ] 外貌锚点每条都能被生图模型理解（没有「气质优雅」这种废话）
- [ ] 性格有三层，不是一堆形容词堆砌
- [ ] 能力都写了**限制**
- [ ] JSON 的 `first_mes` 有场景+动作+对话，且没写死用户名字
- [ ] `mes_example` ≥ 4 组，覆盖不同情绪
- [ ] 世界书 keys 是用户真会打的词，不是设定术语
- [ ] 漫剧卡没有混入 SD 权重语法
- [ ] 所有推断内容都已标注，没有把编的当成测的
